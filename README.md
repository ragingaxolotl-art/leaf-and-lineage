# Leaf & Lineage


## Pattern Lab: creative breeding

[Open Pattern Lab](https://ragingaxolotl-art.github.io/leaf-and-lineage/pattern-lab/) · [Pattern Lab teacher setup](https://ragingaxolotl-art.github.io/leaf-and-lineage/pattern-lab/?teacher=1)

Pattern Lab is a buildless browser game with original vector beetles, designed for mouse, keyboard, touch and Chromebooks. There are no predators or automatic mating. Click a beetle, inspect it larger, and add it to either four-slot parent jar. Tank beetles can also be dragged into a jar. Use two parents for an exclusive cross or three/four for randomly mixed pairings within that jar. Each click on **Breed selected jars** creates 10–20 babies total; two complete active jars split the brood, with an odd extra assigned randomly. Parents stay until deliberately moved. Every baby records its two actual parents, jar, brood and lineage generation. Repeated broods are siblings, not new descendant generations.

The top-down breeder tank holds 48 individuals; overflow waits in the nursery without deleting existing beetles. **Cool & pause** gives a brief pretend mist and freezes motion. Running resumes wandering, not breeding. Movement speeds include 0.5×, 1×, 2×, 5× and 10×, separate from inherited walking speed. Backgrounds are decorative. A separate top-down **Keep tank** holds ten favorites, unchanged by later broods. Move one out before adding an eleventh. Save a tank file or **Save Keep tank + family file** to download the complete experiment, favorites, inherited copies, notes and parentage. Open tank file restores it. This is a local browser experiment with no accounts, trackers or external fonts; online code sharing sends only the selected anonymous beetle packet to the dedicated Supabase project.

The invented genetics model has 80 paired loci on seven chromosome pairs: body/pattern colors, dominant pattern suppressors, one/two-color gates, mark shape, distribution, size and symmetry; 13 antenna frameworks with tiny-to-long variants and separate fine-hair modifiers; eight leg frameworks with quantitative modifiers; additive motor speed, stride and strength. A gamete samples one homolog per chromosome, with a 35% game-model chance of one crossover. Optional mutation acts on transmitted copies independently. Hidden modifiers and colors remain real inherited copies. Developmental variation is fixed at birth; inspecting or cooling never rerolls a specimen. This is not a model of an actual beetle species, physiological strength, or measured crossover rates.

Teacher links preserve starting seed, mutation, bedding permissions, movement speed and whether students see all genetic copies and simulation-based offspring forecasts. Seeds reproduce founders; actual births use fresh random rolls. Forecasts use a separate fixed simulation stream, so inspecting odds never consumes actual breeding draws. Class links contain a checked PL1 code; damaged codes show an error rather than silently replacing the starting conditions. Settings are guidance, not a secure exam lock. Save files contain the complete genome even when the student interface hides it.

To run locally, serve `dist/` and open `/pattern-lab/`, or open the self-contained `Pattern-Lab.html` download. No build or dependencies are required. The repository workflow runs the full model, link-code and frozen-Simplified tests before publishing `dist/` to GitHub Pages. Pattern tests cover parental transmission/linkage, hidden-gene crosses, within-jar parent selection, split totals, fresh streams, unchanged parents, the ten-favorite cap, nursery overflow, save integrity, class codes, and rendering every antenna/leg combination. Device performance still depends on the school Chromebook; the active tank is capped and drawings are cached in the DOM.

## Make a student link

1. Open **Classroom setup**.
2. Set the row count, starting population, solid or Neapolitan habitat, seed, selection strength, mutation rate (a whole number from 0 to 20%), and animation speed.
3. Choose **Bird mode only**, **Breeding mode only**, or **Both · students can switch**.
4. Check **Students may change environments** if students should control their own backgrounds. Otherwise the assigned environment stays fixed.
5. Check **Show students all stats and genetics** to reveal the full measurements, history chart, inherited gene copies, family parentage, offspring odds for allowed breeding, and detailed data downloads. Leave it unchecked for the simplified student view.
6. Press **Create student link → Copy student link** and paste the complete link into the assignment. **Preview student view** shows exactly what students receive.

The code is already included in the link. Shared links also include the current release in the page address so an older cached page does not reject a newer code. If a class link displays an error, **Reload latest lab** requests a fresh page while preserving the full code. A damaged code is still rejected rather than replaced by default settings. Previously shared codes keep their starting settings while using the current genetics, camouflage, palette, and mating rules. Students open directly into the chosen preset, with the chosen statistics visibility already applied. Full stats shows experiment settings as read-only values; it does not unlock settings sliders or teacher setup. Environment permission and activity permissions travel with the code. A bird-only class has no jars or breeding switch; a breeding-only class has no bird controls. With both enabled, students can switch between choosing parents and natural selection. Choosing parents and bird selection are separate activities; the bird does not automatically hunt after a manual breeding step.

When environment changes are allowed, students get Meadow, Dry leaves, Dusk, Neapolitan, and a custom color picker. Changing the background preserves every existing beetle and its genes. It affects camouflage and future natural selection. Controls pause during a generation transition, then become available again. Switching environments during breeding changes the background but does not introduce bird selection.

**Start over** restores the assigned starting population, habitat, and activity. Notes remain until the page closes or reloads. A preset code contains starting conditions, not student information or a saved game. The same seed and presets give everyone the same starting beetles. Bird survival uses fresh independent randomness, separate from the starting seed, so restarting the same preset does not replay the same hunt. Chance may still produce matching outcomes occasionally. The teacher can paste a code or full student link under **Reuse an existing class code** to load its setup.

New links use `LL4` codes, which include the full-stats choice and the Neapolitan layout with three colors. Older `LL3` codes retain their full-stats choice and use a solid habitat. Older `LL2` links retain their activity and environment permissions, with full stats off. Previously shared `LL1` links remain valid, enabling both activities and a fixed environment. They use the revised inheritance model, so older codes retain their setup choices but do not reproduce the previous genetics model's exact beetles. Codes simplify the classroom view; they are not authentication or an assessment security boundary. The source and open teacher lab remain public.


### Sumo, inherited instincts and portable beetle documents

The sumo table uses deterministic 60 Hz movement/contact physics, with fresh match seeds. It never preselects a winner or changes living beetles. A center crossing the inner white line is a ring-out; 60 seconds without one is a draw. Tracking, reaction, focus, pushing/wandering instincts, turning, ring tactics, edge awareness, bracing, sideways balance, grip, endurance, recovery, mass, acceleration, center preference, curiosity, social approach, caution and persistence have continuous inherited copies. Existing speed and strength contribute too. Front, side and rear contacts use different support; mass improves resistance but slows acceleration and turning. Playback and viewport size do not change results.

Added appearance traits include body length, head width, horns, jaws, shell gloss, metallic sheen, ridges, shield width and gait rhythm. Appearance choices are independent from a universal fitness ranking. The comparison view respects classroom detail visibility; family trees follow actual parents. The match notebook saves replay seeds, contact records and participating genetic packets. These are invented game measurements, not biological intelligence or real-species performance claims.

Export beetle JSON or an enlarged specimen's printable HTML document. Both can be re-uploaded through **Import beetle file**, preserving all alleles and the development seed without replacing existing beetles. The HTML document includes inert JSON data; the importer never executes uploaded HTML. Printed PDFs are readable reports, while HTML/JSON retain importable data. Version-one tank saves are upgraded deterministically: the original five chromosome pairs and kept beetles remain, while new traits are initialized once and labeled as an upgrade.

To connect two screens, open **Challenge another screen**. The host selects its red beetle and creates an eight-character code. A second child selects their own red beetle, enters that code, and sends it to the host's blue corner. The host starts the match. Both screens receive the same genetic packets, seed and start time, and simulate the same contest. Create a new room to choose different participants. Only two participants may join; only the host can start or close a room. Codes expire after two hours. No student accounts, personal names, notes or full tank files are uploaded. Local contests and data files work without the sharing service.

## Each jar replaces only its row

Every row has room for eight beetles and its own generation counter. In bird mode, mating favors nearby survivors across rows, columns, and diagonals, with lower distance weights for each individual farther partner. In jar mode, each jar controls its own row. Drag two different living beetles into its jar, or select a beetle and click an empty + slot. Press **Breed row** to replace only that row. Empty and unfinished jars leave their rows unchanged.

**Next generation** advances all complete jars once. **Play** continues advancing complete jars until paused. Parents may come from any row and may be reused across jars. **Use pair in all jars** explicitly copies the active pair. Original parents stay saved in their jars, even after their offspring replace the row or the activity switches. Each later brood uses the same original pair until a parent is replaced or removed. Repeated broods of a pair are siblings rather than descendant generations. Select offspring as new parents to follow inheritance down later generations. Global **Round** counts completed experiment steps; row generations can differ.

In bird mode, every insect gets one independent survival roll. The bird can eat any number, including zero or all. Any two distinct survivors can be parents. Mating is weighted by spatial distance in every environment, including solid and custom colors: ring 1 contains the eight surrounding leaves, ring 2 is two leaf steps away, and so on. Each individual candidate has distance weight `0.5^(distance-1) / distance`: 1 for an adjacent beetle, 0.25 at two rings, about 0.083 at three, and progressively less farther away. A weighted draw chooses a partner from all distinct real survivors. More beetles in a ring do not divide that ring’s fixed share; each individual keeps its own weight. With eight adjacent candidates and one at two rings on the same background, each adjacent candidate has about 12.12% chance, while the farther individual has about 3.03%. All farther survivors retain nonzero weight.

Movement between unlike habitat patches is reduced by a separate symmetric factor `0.05 + 0.95 × match(backgroundA, backgroundB)^8`. Identical backgrounds give factor 1, including matching custom colors; strongly different backgrounds approach 0.05. Multiply the individual distance weight by this factor. This is an invented patch-movement rule, not measured beetle behavior. No color-family label enters it. It reduces gene flow across unlike patches without forbidding any cross-boundary parent. Distance comparisons assume the same background affinity; a farther beetle in the same patch can outweigh a nearer beetle across an unlike patch.

The first parent remains the survivor on the destination leaf. Vacant leaves use a nearest survivor, choosing between distance ties with the same background-affinity factor. No beetle’s color is changed to fit the destination. With at least two survivors, their offspring refill every row. A lone survivor stays on its original leaf without offspring; zero survivors leaves the board empty. There is no forced survivor quota, rescue selection, or reroll. Natural selection measures each insect against its own leaf, then chooses surviving parents across rows for reproduction. The bird report counts offspring whose parents came from different rows, and full genetic details record those parental rows. Contrasting beetles are more likely to be eaten when selection is strong, but chance remains. With animation enabled, the bird visits every living beetle and rolls only when it reaches that leaf. The progress counter shows completed checks, eaten beetles, and survivors so far. It never forecasts future victims. Reproduction begins only after all checks, and completed rolls are not repeated. Turning the animation off does not turn selection off. Reduced-motion preferences skip the moving bird.

**Next generation** advances exactly once. **Play** keeps advancing, and becomes **Pause** while running. Speed choices are 0.5×, 1×, 2×, 4×, 5×, and 10× in the teacher lab and classroom presets. Speed scales bird travel, checks, breeding transitions, and the gap between rounds; it does not change survival probabilities or inheritance. This works in both bird and breeding modes. Breeding Play reuses the original parents in each complete jar; it does not automatically choose new offspring as parents. Empty jars never auto-fill. Selecting a beetle pauses playback. A generation already in progress finishes when paused. Playback stops when the tab is hidden or no beetles remain in bird mode, and reset cancels transitions. On small screens, swipe sideways along a row; its jar stays at the left. Mouse, trackpad, touch, pen, and keyboard click-to-add are supported.

## Neapolitan environments

Neapolitan is a fourth environment beside Meadow, Dry leaves, and Dusk. It divides the board’s leaf area into three continuous vertical bands of equal width, with colors set by the teacher. The bands span all rows and the spaces between them. The defaults are Meadow, Dry leaves, and Dusk. Each insect’s camouflage and survival chance use the band directly behind its own leaf. With eight leaf columns, columns 1–3 occupy the left third, 4–5 the middle third, and 6–8 the right third. The jars sit outside these survival zones.

The teacher can share a fixed Neapolitan preset or allow students to switch environments. Changing layouts or colors never changes existing beetles or their genes. Surviving parents breed across rows, columns, diagonals, and habitat boundaries using the same individual distance and habitat-affinity rules in every environment. Offspring stay near the first parent, rather than being globally reshuffled. Local survival, reduced crossing between unlike patches, and reproduction let matching colors form bands, with gene flow from farther mates. Bands are not guaranteed to be uniform, particularly in small populations. Every advantage is calculated from the actual leaf background, including three custom colors. Every parent is a distinct real survivor; there is no forced color placement or guaranteed band. Jar offspring fill only their jar’s row. Full stats shows each selected insect’s actual background and survival chance.

## Inherited surprises — teacher reference

Each beetle carries two real inherited color recipes. Each baby gets one complete recipe from each parent, with an independent 50/50 transmission choice per parent. Six linked binary genes encode a recipe: three bits choose one of eight color families, and three bits encode expression strength from 0 to 7. The stronger recipe supplies the base color; equal strengths use the copy from parent A. Shade genes also affect the actual visible color. Expression strength travels with the recipe, so no color has a built-in dominance advantage. The other recipe remains in that beetle’s genes and can pass to descendants. A green carrier of a weaker red recipe crossed with another such carrier has a 25% chance of offspring expressing that red recipe before mutation; shade genes determine the exact appearance. Other crosses have other possibilities. There is no invisible ancestral archive or randomly assigned surprise color.

This replaces the old interacting-switch rule, which disproportionately produced green. With uniformly distributed recipe colors and expression strengths, all eight expressed base recipes now have exactly equal representation. Mixed starting populations use uniformly random recipe bits, apart from two green carriers supplied for the inheritance example. The same seed remains reproducible within this version, but earlier versions’ exact starting beetles change.

The eight recipe codes select green (122,156,80), yellow (209,178,65), red (190,95,76), orange (255,117,61), blue (103,129,182), teal (65,165,160), purple (171,68,178), or mixed (255,90,163). Three independent shade genes each have two integer copies from 0 to 255. Let `q` be their mean for a channel and `base` the expressed recipe channel. If `q ≤ 128`, the channel is `base × q / 128`; otherwise it is `base + (255-base) × (q-128) / 127`. Thus 0 is fully dark, 128 retains the recipe, and 255 is fully bright. Every recipe can reach the entire RGB range, including black and white, within the rounding resolution of inherited gene copies. Unlike the previous ±32 limit, custom colors have no hard palette ceiling. Reaching a color through selection still takes time and depends on inherited variation and mutation. Starting shade copies cluster near 128 so starting recipes remain recognizable. Genetic transmission, phenotype, and mutation do not read the habitat.

Starting scenarios include mixed visible colors, green carriers of blue recipes, and green carriers of yellow or red recipes. **Try an inheritance cross** selects two living green carriers and turns mutation off. The preview enumerates four equally likely recipe transmissions and 64 shade transmissions (256 total), grouping duplicate RGB outcomes with their probability weights. Visible-family probabilities classify the actual predicted colors, including black, white and gray; they are separate from recipe transmission odds. Every baby is an independent draw; eight babies need not match the predicted proportions. Full stats reveals the actual recipes, expression strengths, shade genes, and parental records. Color names describe actual appearance using hue, saturation and brightness; an expressed green recipe can shift to another visible family through shade genes. The simplified view hides these details.

Mutations are separate from inherited recipes. A transmitted binary copy may flip between 0 and 1; a shade copy may shift by ±1–36, staying within 0–255. The mutation rate applies independently to 18 inherited copies. Mutations do not target the environment. Use 1–3% to observe color selection; high rates such as 20% repeatedly disrupt inherited color combinations. A copy lost from every living beetle is not kept in an invisible ancestral archive; reintroduction requires mutation. Parent IDs and actual inherited copies are retained in the teacher data export.

Camouflage uses one channel-symmetric rule for every color: `exp(-4 × d² - 12 × balance)`. Here `d²` is mean squared normalized RGB distance. To calculate `balance`, subtract each color’s minimum channel and divide by its channel range; take the mean squared difference between those two normalized color directions, then multiply by the smaller channel range divided by 255. If either range is zero, balance is zero. This distinguishes green from similarly bright brown, while avoiding unstable hue comparisons for black, white, or near-gray colors. Permuting red, green, and blue channels together in beetle and background leaves the score unchanged. No color-family label enters the survival calculation. This invented score is not a full model of bird vision. Every living insect starts with base survival probability `(1-pressure) × 0.7 + pressure × (0.1 + 0.8 × camouflage²)`. At zero pressure, survival ignores color and has a 70% chance for every insect. At full pressure, perfect camouflage gives 90% base survival, while very poor camouflage approaches 10%. The game adds a local neighbor effect. It compares the eight surrounding leaves, including diagonals, excluding empty leaves, row wrapping, and adjacent leaves on a different habitat color. For each neighbor, compute the positive camouflage advantage `max(0, own_camouflage - neighbor_camouflage)`. Average this over all eligible neighbors, including zero advantages. The bonus is `(1-base_survival) × 0.6 × pressure × average_advantage`, added to base survival. More contrasting neighbors offer more protection; matching neighbors give zero extra protection. As a population becomes similar, the boost fades while ordinary camouflage remains. Uniform matching beetles still have only a 10% eating risk at full pressure. The boost reduces remaining eating risk by at most 60%, never guarantees survival, and is zero when selection is off. This is an invented game rule, not a claim about measured bird behavior.

Neighbor comparisons use the population and leaf positions at the start of the hunt. Animated removals do not alter the model population until checks finish, so checking order does not change odds. Every insect still gets exactly one fresh roll, and outcomes are not forced. Full stats separates base survival from the neighbor boost; the full CSV contains both and the number of compared neighbors.

The population size is not used to force a target survivor count. With at least two survivors on the board, each offspring has two distinct surviving parents: using the same individual distance and habitat-affinity rules in every environment. Diversity measures color spread; the teacher chart combines all row populations after each round.

This invented recipe model illustrates inherited variation, hidden alleles, linkage, selection, mutation, and drift. It does not claim to reproduce actual beetle color genetics. Color genes travel together as a linked recipe; shade genes inherit independently. Each row has capacity eight and bird-mode survivors mate across rows, and selection depends on camouflage, local neighbor contrast, and chance.

## Run or download

Open **Leaf-and-Lineage.html** in a current browser for a self-contained offline version, where school device policy permits local HTML. Alternatively keep all five files in `dist/` together and run:

```sh
python3 -m http.server 8000 --directory dist
```

Open http://localhost:8000. Share hosted URLs for access on other devices. A downloaded page's local file address is not shareable across devices.
